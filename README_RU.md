## Обзор: Архитектура v0.8.0

**PRZM** (PrismLZ) — это сверхскоростная, математически унифицированная система архивного сжатия данных, спроектированная для преодоления классических пределов одномерного скользящего окна (Zstandard, LZMA, Brotli) путём отображения нелинейных цифровых распределений на искривлённые дискретные многообразия.

Архитектура PRZM объединяет высокопроизводительное ядро на **Go 1.27**, аппаратные ядра **NVIDIA CUDA (`gpu/`)** и полностью автономный **декомпрессор на чистом C99/C11 со строго нулевыми аллокациями (`libprzm_dec`)**. Система создана для интеграции на линейной скорости памяти в высоконагруженные сценарии: игровые движки (Unreal Engine, Unity, Godot), GPU-пайплайны потоковой загрузки ассетов, движки баз данных и FFI-биндинги (Rust, C++, Zig, Python).

## Ключевые архитектурные особенности и инварианты

1. **Строгий контракт нулевых аллокаций**: Строго **0 динамических аллокаций в куче** (`0 B/op, 0 allocs/op`, ноль вызовов `malloc`/`free` в процессе потоковой декомпрессии) как в Go (`DecompressTo`), так и в чистом C (`przm_decompress`). Память выделяется вызывающей стороной в фиксированных буферах или стековых аренах.
2. **Линейная скорость микроархитектуры**: Декомпрессия достигает **4.57–6.16 ГБ/с** на стандартных слитных фреймах (и до **58.7 ГБ/с** на специализированных алгебраических многообразиях), потребляя $O(1)$ процессорных тактов на векторный блок и полностью насыщая шину памяти.
3. **Аппаратное ускорение NVIDIA CUDA (`gpu/`)**: Нативная интеграция с NVIDIA Driver API без накладных расходов CGo (`gpu/bridge.go`), исполняющая кастомные PTX-ядра (`sm_86` Ampere, CUDA 13.4). Обеспечивает **40+ ГБ/с параллельного LZ77-поиска**, Warp-токенизацию и Device-to-Device (D2D) сжатие прямо в видеопамяти с бесшовным откатом на CPU на машинах без GPU.
4. **Оптимизация искажений Trellis RDO**: Заменяет жадный поиск совпадений динамическим программированием на ориентированном ациклическом графе (DAG). Точная функция побитовой стоимости согласует литеральные серии, длины совпадений и 4-регистровый LRU-кэш дистанций, ликвидируя оверхед по смещениям.
5. **Архитектура демультиплексирования Mode 8 Tri-Stream**: Разделяет поток команд на 3 независимых канала (`opStream`, `metaStream` и `varStream`). Равномерно распределённые словарные индексы и расширенные длины изолированы от низкоэнтропийных структур, что предотвращает загрязнение таблиц частот энтропийного кодера.
6. **Неархимедов $p$-адический поиск совпадений**: Поиск совпадений на уровнях 3/4 использует ультраметрический подъём Гензеля по многоуровневым хэш-таблицам, обеспечивая **ускорение поиска в 2.03x** (26.3 нс против 54.6 нс при глубине 64) с математической гарантией отсутствия ложных пропусков кандидатов (теоремы HL1/HL2).
7. **Статический словарь RFC 7932**: Встроенный предобученный словарь на 14 016 слов и матрица из 121 трансформации с $O(1)$ хэш-индексацией, обеспечивающие мгновенные совпадения нулевой стоимости для веб-данных, JSON, HTML и исходного кода.
8. **Формальная верификация в Lean 4**: Ключевые алгебраические симметрии, инволюции и топологические свойства математически доказаны в **Lean 4** со строго **0 конструкциями `sorry`** во всех 33 модулях доказательств (`proofs/PRZM/*.lean` и `proofs/*.lean`).
9. **Интероперабельность Clean Room**: 100% битовая идентичность между эталонным кодеком на Go и чистым C99-декодером (`tests/test_przm_dec.c`, 21/21 тест пройден).

## Аппаратное ускорение на CUDA GPU (`gpu/`)

Пакет `gpu/` реализует конвейер аппаратного сжатия напрямую на графических процессорах NVIDIA, используя чистый Go и системные вызовы к Driver API (`nvcuda.dll` / `libcuda.so`), **без использования CGo**:

```
                       АППАРАТНЫЙ КОНВЕЙЕР CUDA
┌─────────────────┐       DMA HtoD       ┌──────────────────────┐
│  Память хоста   │ ═══════════════════> │ Видеопамять (Pinned) │
│  (Pinned-блоки) │                      └──────────┬───────────┘
└─────────────────┘                                 │
                                    ┌───────────────┴───────────────┐
                                    │ Параллельный Radix-Strike     │
                                    │ LZ77-кернел (PTX sm_86)       │
                                    │ - 40+ ГБ/с поиск совпадений   │
                                    └───────────────┬───────────────┘
                                                    │
                                    ┌───────────────┴───────────────┐
                                    │ Warp-токенизатор потока       │
                                    │ - Сборка команд и смещений    │
                                    │ - Device-to-Device (D2D)      │
                                    └───────────────┬───────────────┘
                                                    │
┌─────────────────┐       DMA DtoH                  │
│ Бинарный поток  │ <═══════════════════════════════┘
│ PRZM (сжатый)   │
└─────────────────┘
```

- **Двойная буферизация DMA**: Перекрывает передачу данных через шину PCIe с вычислениями ядер с помощью асинхронных CUDA-потоков.
- **Параллельный поиск Radix-Strike LZ77**: Кастомное PTX-ядро обрабатывает скользящие окна от 64 КБ до 8 МБ на тысячах ядер GPU одновременно.
- **Warp-токенизатор**: Формирует Секцию 2 (Команды), Секцию 3 (Смещения) и Секцию 4 (Литералы) прямо в VRAM без обратной пересылки в оперативную память CPU.
- **Архитектура Zero-CGo**: Динамическая загрузка функций Driver API через системные вызовы Go, обеспечивающая мгновенную сборку без задержек CGo.
- **Плавный фоллбэк**: Автоматическое определение оборудования и переключение на CPU Trellis на системах без видеокарт NVIDIA.

## Бинарная топология фреймов

Стандартный фрейм PRZM состоит из 8-байтового глобального заголовка и 4 изолированных, независимо декодируемых секций:

```
[Magic: 4B ("PRZM")] [Flags: 1B] [UncompressedSize: 3B LE]
[Optional Stride: 0..1B] [Optional DictID: 0..4B]
[Каталог секций: 4B или 6B]
  ├── Секция 1: Параметры распределения и логарифм окна (8 байт)
  ├── Секция 2: Поток команд (Mode 8 Tri-Stream: opStream, metaStream, varStream)
  ├── Секция 3: Поток смещений (49-интервальный кодбук, Mode 12 V-ANS, 4-регистровый LRU)
  └── Секция 4: Поток литералов (Raw-байты, Nibble-Planes или 4-поточный SIMD V-ANS)
```

## Использование API

### API чистого C99/C11 (Zero Allocation)

Автономный декомпрессор (`src/przm_dec.c` / `src/przm_dec.h`) **не имеет внешних зависимостей** и работает исключительно в предоставленной памяти:

```c
#include "przm_dec.h"
#include <stdio.h>
#include <stdlib.h>

void decompress_example(const uint8_t* compressed, size_t comp_len) {
    // 1. Запрос точного размера несжатых данных за время O(1)
    int64_t u_size = przm_get_uncompressed_size(compressed, comp_len);
    if (u_size < 0) {
        fprintf(stderr, "Повреждённый или некорректный фрейм PRZM\n");
        return;
    }

    // 2. Выделение буфера назначения с запасом безопасности
    size_t out_cap = (size_t)u_size + PRZM_SAFETY_PADDING;
    uint8_t* out_buf = (uint8_t*)malloc(out_cap);

    // 3. Декомпрессия со СТРОГО НУЛЕВЫМИ аллокациями в куче (0 B/op)
    int64_t written = przm_decompress(compressed, comp_len, out_buf, out_cap);
    if (written != u_size) {
        fprintf(stderr, "Ошибка декомпрессии: %lld\n", (long long)written);
        free(out_buf);
        return;
    }

    printf("Успешно распаковано %lld байт на линейной скорости шины!\n", (long long)written);
    free(out_buf);
}
```

### Высокоуровневый API на Go (Декомпрессия на месте без аллокаций)

```go
package main

import (
	"fmt"
	"log"

	"github.com/lemon4ksan/foundation/bufkit"
	"github.com/lemon4ksan/przm"
)

func main() {
	payload := []byte("Автономное геометрическое архивное сжатие на дискретных многообразиях!")

	// 1. Сжатие на Уровне 3 (Trellis RDO + подъем Гензеля)
	compressed, err := przm.Compress(payload, 3)
	if err != nil {
		log.Fatalf("Сжатие не удалось: %v", err)
	}

	// 2. Выделение выровненного буфера под кэш-линию
	dst := bufkit.AlignedBytes(len(payload)+64, bufkit.CacheLineSize)

	// 3. Декомпрессия на месте со СТРОГО 0 аллокаций в куче
	n, err := przm.DecompressTo(compressed, dst)
	if err != nil {
		log.Fatalf("Декомпрессия не удалась: %v", err)
	}

	fmt.Printf("Распаковано %d байт: %s\n", n, string(dst[:n]))
}
```

### API аппаратного сжатия на CUDA GPU

```go
package main

import (
	"fmt"
	"log"

	"github.com/lemon4ksan/przm/gpu"
)

func main() {
	if !gpu.IsAvailable() {
		fmt.Println("NVIDIA GPU не обнаружен, откат на CPU")
		return
	}

	compressor, err := gpu.GetGlobalCompressor()
	if err != nil {
		log.Fatal(err)
	}

	data := make([]byte, 16*1024*1024) // 16 МБ полезной нагрузки
	// ... заполнение данных ...

	// Device-to-Device (D2D) сжатие с нулевым копированием
	compressed, profile, err := compressor.CompressD2D(data)
	if err != nil {
		log.Fatal(err)
	}

	fmt.Printf("Сжато %d МБ -> %d байт на GPU (Время ядра: %.2f мс, Ingress: %.2f ГБ/с)\n",
		len(data)/(1024*1024), len(compressed), profile.KernelTimeMs, profile.IngressDMABandwidthGBps)
}
```
