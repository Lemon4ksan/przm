PRZM — это сверхскоростная, математически унифицированная система архивного сжатия данных, выходящая за рамки классических ограничений одномерного скользящего окна (zstd, LZMA, Brotli) за счёт отображения нелинейных цифровых распределений на искривлённые дискретные многообразия.

PRZM включает в себя как полноценную реализацию на **Go 1.27** с SIMD-ускорением (`simd/archsimd`), так и автономный, не требующий внешних зависимостей **декомпрессор на чистом C99/C11 с нулевыми аллокациями (`libprzm_dec`)**, спроектированный для интеграции на линейной скорости шины в высокопроизводительные системы: игровые движки (Unreal Engine, Unity, Godot), пайплайны потоковой передачи GPU, загрузчики ассетов, движки баз данных и интерфейсы FFI (Rust, C++, Zig, Python).

## Ключевые архитектурные особенности и инварианты

1. **Строгий контракт нулевых аллокаций**: Строго **0 динамических аллокаций в куче** (`0 B/op, 0 allocs/op`, ноль вызовов `malloc`/`free` в процессе потоковой декомпрессии) как в Go (`DecompressTo`, `DecompressIsoQuant`, `DecompressHeisenberg`, `DecompressMobiusTo`, `DecompressMargolusTo`, `PWSDecodeTo`), так и в Pure C (`przm_decompress`).
2. **Линейная скорость микроархитектуры**: Декомпрессия достигает **до 58.7 ГБ/с** (граница $O(1)$ циклов на блок), потребляя от **2.63 до 3.5 тактов процессора на 64-байтный векторный блок**, полностью насыщая пропускную способность аппаратной шины памяти и кэша L1.
3. **Формальная верификация в Lean 4**: Ключевые алгебраические симметрии, инволюции и топологические свойства математически формализованы и верифицированы на компьютере в **Lean 4** со строго **0 конструкциями `sorry`** во всех 33 модулях доказательств (`PRZM/*.lean`).
4. **Неархимедов $p$-адический поиск совпадений**: Поиск совпадений на уровнях 3/4 заменяет линейные цепочки хэшей ультраметрическим подъёмом Гензеля, обеспечивая **ускорение поиска в 2.03x** (26.3 нс против 54.6 нс при глубине 64) с математической гарантией отсутствия ложных пропусков кандидатов (теоремы HL1/HL2).
5. **Битовая идентичность без потерь**: 100% двусторонняя кросс-языковая совместимость между компрессором на Go и декомпрессором на Pure C на всех поддерживаемых профилях данных.

## Почему Go?

**Потому что Go — это весело!** Но помимо этого, он даёт колоссальные технические преимущества для данной архитектуры:

1. **Элементарный параллелизм:** PRZM разбивает данные на независимые блоки (64KB - 8MB). Нативные горутины и планировщик (work-stealing) делают распараллеливание кодера по всем ядрам процессора абсолютно тривиальной задачей по сравнению с потоками в C++.
2. **Интеграция Ассемблера и SIMD:** Go позволяет писать чистые `.s` файлы на ассемблере (AVX2/AVX-512/NEON) для тяжёлых математических преобразований (нормализация Base64, BitPlane, BCJ), при этом окружающая логика маршрутизации остаётся безопасной для памяти.
3. **Кросс-компиляция:** С помощью `GOOS` и `GOARCH` мы можем скомпилировать CLI утилиту PRZM под Windows, Linux, macOS, ARM и x86 одной командой, без мучений с конфигурациями CMake.
4. **Скорость без ущерба безопасности:** *Компрессор* работает в безопасной среде Go, предотвращая переполнения буфера при сложном анализе графов (DAG-парсинг). При этом *Декодер* (`DecompressTo`) полностью обходит сборщик мусора (GC) благодаря строгому контракту `0 allocs`, достигая скорости чистого C, но сохраняя надёжность Go при чтении заголовков.

## Использование API

### Pure C99/C11 API (Zero Allocation)

```c
#include "przm_dec.h"
#include <stdio.h>
#include <stdlib.h>

void decompress_buffer(const uint8_t* compressed, size_t comp_len) {
    // 1. Запрос точного размера выходного буфера за время O(1)
    int64_t u_size = przm_get_uncompressed_size(compressed, comp_len);
    if (u_size < 0) {
        fprintf(stderr, "Повреждённый поток PRZM\n");
        return;
    }

    // 2. Выделение буфера с запасом безопасности (safety padding)
    size_t out_cap = (size_t)u_size + PRZM_SAFETY_PADDING;
    uint8_t* out_buf = (uint8_t*)malloc(out_cap);

    // 3. Декомпрессия со СТРОГО НУЛЕВЫМИ аллокациями в куче
    int64_t written = przm_decompress(compressed, comp_len, out_buf, out_cap);
    if (written < 0 || written != u_size) {
        fprintf(stderr, "Ошибка декомпрессии: %lld\n", (long long)written);
        free(out_buf);
        return;
    }

    printf("Успешно распаковано %lld байт на линейной скорости шины!\n", (long long)written);
    free(out_buf);
}
```

### Go API (Декомпрессия на месте без аллокаций)

```go
package main

import (
	"fmt"
	"log"

	"github.com/lemon4ksan/foundation/bufkit"
	"github.com/lemon4ksan/przm"
)

func main() {
	data := []byte("Autonomous geometric compression across discrete Riemannian manifolds!")

	// Сжатие на Уровне 3 (с ультраметрическим поиском Гензеля)
	compressed, err := przm.Compress(data, 3)
	if err != nil {
		log.Fatal(err)
	}

	// Выделение выровненного буфера
	dst := bufkit.AlignedBytes(len(data)+64, bufkit.CacheLineSize)

	// Декомпрессия на месте без выделения памяти в куче
	n, err := przm.DecompressTo(compressed, dst)
	if err != nil {
		log.Fatal(err)
	}

	fmt.Printf("Распаковано %d байт: %s\n", n, string(dst[:n]))
}
```
