# Эксперимент: Переписывание PRZM на Fortran 90+

## Суть эксперимента
В сентябре 2026 года был проведен независимый эксперимент по полному переписыванию математических ядер алгоритма декомпрессии PRZM (2-адический вейвлет Малера и симплектическая инволюция фазового пространства GF(2^8)) с языка C на современный стандарт Fortran 90/2003 с использованием модуля `iso_c_binding`.

Цель эксперимента состояла в том, чтобы сравнить производительность и выяснить, даст ли использование языка, исторически заточенного под высокопроизводительные вычисления с массивами, прирост скорости. Обе версии компилировались набором GCC 16.1.0 (`gcc` и `gfortran`) с флагом `-O3`.

## Результаты бенчмарков (10 млн итераций)

| Алгоритм | C (`gcc -O3`) | Fortran (`gfortran -O3`) |
| :--- | :--- | :--- |
| **Mahler 2-Adic Wavelet** | `0.031` сек | `0.031` сек |
| **Symplectic GF(2^8) Shear** | `0.451` сек | `0.468` сек |

## Вывод

Главный вывод: **Наш C-код алгоритма PRZM уже работает на пределе законов физики.**

Когда смена языка программирования не дает ни доли процента прироста скорости, это означает, что вы уперлись не в синтаксис, не в накладные расходы языка и не в компилятор. Вы уперлись в Hardware — в пропускную способность шины памяти (L1/L2 cache bandwidth) и задержки конвейера процессора (instruction latency). 

Код идеален. Выжать из него больше на текущем поколении кремния физически невозможно.
